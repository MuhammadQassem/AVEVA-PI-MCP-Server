## 1.1.0 (2026-10-29)

Extended by Muhammad Qassem ([MuhammadQassem/AVEVA-PI-MCP-Server](https://github.com/MuhammadQassem/AVEVA-PI-MCP-Server)). All 1.0.0 behaviour is unchanged unless the new switches are turned on.

### Features

* **tools:** AF build tools (`pi.build.*`, create-only, `MCP_BUILD_TOOLS_ENABLED`): `apply_plan` (whole structure from one plan, dry run by default, dependency-ordered and idempotent), `create_database`, `create_category`, `create_unit`, `create_table`, `create_element_template`, `create_attribute_template`, `create_element`, `create_attribute`, `create_analysis` (Expression and Rollup), `create_pi_points`.
* **tools:** AF modify tools (`pi.modify.*`, `MCP_MODIFY_TOOLS_ENABLED`, never delete, dry run with old → new diff by default): `update_attribute_template`, `update_attribute`, `update_element` (including template change), `set_attribute_values` (static attributes only), `update_table_data`.
* **config:** `MCP_BUILD_TOOLS_ENABLED`, `MCP_BUILD_ALLOWED_DATABASES` (database paths or `\\Server\*`), `MCP_MODIFY_TOOLS_ENABLED`, with startup validation (requires `MCP_READ_ONLY=false`, stdio transport, a non-empty allow-list).
* **tools:** PI Point attributes get `pointtype=` automatically so AF can create their tags.

### Bug Fixes

* **auth:** Kerberos/Negotiate failed with an internal error when PI Web API advertised several `WWW-Authenticate` methods (e.g. Negotiate and Basic), because undici returns them as an array.
* **errors:** "Tool execution failed" log lines dropped the error (pino context object was passed after the message).
* **tools:** Build/modify errors now include an actionable (sanitized) detail such as the allow-list violation.

### Documentation

* New [docs/af-build-tools.md](docs/af-build-tools.md) (plan format, Excel workflow, AF limits); tool catalog, configuration reference, README and `.env` templates updated.

## [1.0.0]

Initial stable release.

### Added

- Stateless, zero-trust **Model Context Protocol (MCP) server** exposing the AVEVA PI System Web API to MCP clients.
- **Outbound authentication modes** to PI Web API: `anonymous`, `basic`, `kerberos` (Negotiate/SPNEGO), and `bearer` (OIDC via AVEVA Identity Manager).
- **Read tools** over time-series archives, AF asset databases, elements, attributes, and summaries.
- **Write tools**, globally **default-deny** (`MCP_READ_ONLY=true` and `MCP_WRITE_TOOLS_ENABLED=false`) with a per-call scope/role gate.
- **Inbound transports:** `stdio` (default, local trust boundary) and `http` with required edge authentication (bearer JWT via JWKS, or mTLS).

### Security

- **Zero-trust posture:** outbound TLS verification enforced in production, over HTTP transport, and with pinning (`NODE_TLS_REJECT_UNAUTHORIZED=0` always blocked at startup; `PIWEBAPI_TLS_VERIFY=false` allowed only as a non-production debugging escape hatch); private-CA trust via `PIWEBAPI_TLS_CA_FILE` unioned with public roots.
- **Single fixed service identity** to PI Web API; inbound caller identity is not propagated upstream.
- **Two-axis auth error-channel:** inbound failures surface as protocol-level errors; all tool-execution failures (including upstream PI 401/403) surface as sanitized `isError` tool results with stable AppError codes.
- Allowlist-based error sanitizer, structured redacted audit logging, and inbound rate limiting / outbound concurrency bounds.
